# 服装店项目上线前检查清单

这份清单用于正式给客户演示和上线 Vercel 前做最后验收。

## 1. 真实手机端验收

- 用 iPhone / Android 打开首页、分类页、商品详情页、联系页。
- 用手机登录 `/admin`，测试拍照上新、编辑商品、快速售出、图片上传。
- 确认所有输入框点击后不会自动放大。
- 确认按钮高度足够，底部保存栏不会被浏览器底栏挡住。

## 2. 图片加载和封面稳定性

- 首页 Hero 图能正常显示。
- 首页分类封面能正常显示；如果图片失效，应出现兜底图标，不应空白。
- 商品卡片主图、详情页主图、多图缩略图都能加载。
- 新上传商品图片应通过后台 `3:4` 裁剪预览并保存为 WebP，适配常见手机竖拍和商品详情比例。
- 删除旧图后重新上传，应立即显示新图。

## 3. 后台效率

- 拍照上新：分类、二级分类、价格、尺码库存、主图上传流程顺畅。
- AI 生成商品资料后，商家需要人工检查名称、描述、材质、颜色。
- 快速售出：实体店卖出一件后，应能按尺码快速扣库存。
- 商品列表：能快速筛选缺图片、库存为 0、未分配尺码、下架商品。

## 4. 在线购物检查

- 商品详情页可以选择有库存的规格并加入购物车。
- Viva Smart Checkout、BOX NOW Locker 和到店自取按店铺设置显示；页面不再提供货到付款。
- 缺货规格不能下单，重复提交不会创建重复订单。
- Viva 成功回跳不能单独确认付款，只有服务端核验 Webhook 可以确认。
- 后台「在线订单」可以查看和处理新订单、创建 BOX NOW 运单、下载标签和复制取货通知。
- 付款超时释放未付款预留；已付款取货超期只标记人工处理，不自动取消或退款。
- 旧 `/feed.xml` 返回 410，确认 Skroutz Feed 已停用。
- 价格是纯数字，不带 `€`。
- 希腊语不乱码。

## 5. SEO 和商用展示

- 首页标题、描述、Hero 文案符合店铺定位。
- 分类页标题准确，例如 Men / Women / Shoes。
- 商品详情页有清楚的商品名、价格、库存、尺码、描述。
- 商品详情页 JSON-LD 不报错。
- `/sitemap.xml`、`/robots.txt` 可以打开。

## 6. 数据安全和备份

- 正式上线前先完成一次数据库 + Storage 完整备份并验证 `manifest.json`；商品 CSV 只能作为维护导出。
- 已按 RPO ≤ 24 小时配置每日完整备份，并保留加密异地副本。
- 已在隔离 Supabase 完成恢复演练，记录 RTO、数据库对账、Storage 对象数量和公开图片抽查。
- 删除商品、删除图片前需要确认。
- Supabase `SUPABASE_SERVICE_ROLE_KEY` 只能配置在服务端环境变量，不得暴露到前台。

## 7. AI 客服边界

- AI 只能回答英语或希腊语，不向顾客展示中文商品字段。
- AI 不得承诺折扣、配送时间、退换货批准、付款可用性、库存一定可买。
- AI 不得说商品已经下单、预留、付款或发货。
- 如果顾客想购买或预留，AI 应提示由店铺确认商品、尺码和库存。

## 8. 订单 / 支付

当前版本使用 Viva Smart Checkout 处理线上预付款，履约方式为 BOX NOW Locker 或到店自取。正式上线前必须先在隔离环境完成 Viva Demo、BOX NOW Stage、Webhook、库存预留、超时释放、运单标签和交付扣减验收；不得把本地单元测试写成真实商户验收通过。
