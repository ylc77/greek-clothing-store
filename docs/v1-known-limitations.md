# v1.0 已知限制

这些限制不是隐藏缺陷，交付前必须与客户确认。

1. 系统目前不接入真实支付终端、税务收银机、希腊 myDATA 或正式发票。POS 是扫码扣减系统库存和内部销售记录，不替代真实收银机或会计系统。
2. Standard/Advanced 的扫码枪、标签机、连续纸偏移、58/80mm 小票和离线条码解码尚需每个真实硬件组合验收；未验收时状态为 `CONDITIONAL`。
3. 浏览器打印不能保证静默打印、自动切纸、钱箱控制或所有驱动的固定边距；需要这些能力时另行评估本地打印桥或厂商 SDK。
4. 库存权威源是单个 `MAIN_STORE`。v1 不提供多仓库、仓间调拨、会计成本核算或实时供应商采购系统。
5. 网站前台是浏览、库存咨询和联系入口，不包含在线购物车、真实线上支付或配送订单履约。
6. Skroutz 只输出资料完整且符合条件的商品。缺少真实品牌、MPN、EAN、英文说明、合规图片、附图、颜色或尺码映射的商品会被安全排除。
7. AI 功能依赖客户自己的低额度 provider key。没有 key 或共享限流不可用时会 fail closed；AI 尺码建议不能替代实际试穿，未提供 size chart 时不会猜测跨体系换算。
8. 法律页面是可配置的零售模板，不替代希腊/欧盟律师、会计师或合规专业人士的正式审查。
9. 备份是维护者主动执行的时间点备份，不是自动连续灾备；RPO 取决于最近一次成功备份。
10. 正式 Vercel/Supabase 案例的技术部署已通过，但 Legal Settings 尚未发布；它只能证明模板部署、权限、事务、Feed 和监控能力，不能证明真实商家法律合规已经完成。
11. 案例 Feed 中的单个演示商品只用于端到端格式验收。客户接入 Skroutz 前必须替换为供应商或品牌方提供的真实品牌、MPN、EAN、图片和商品资料。
